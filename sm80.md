# SM80 MoE GEMM — Integration Plan

## Goal

Port `mixtureExpertKernel.cu` (Flash Attention–style, offline AOT compilation) into the
existing `asym_gemm` Python package (DeepGEMM–style, JIT runtime compilation).  The result
is a single new entry point that dispatches on the input tensor dtype at runtime:

```python
asym_gemm.m_grouped_moe_gemm_nt_contiguous(x, w, o, expert_list, index_list)
# x/w/o dtype: torch.float16 or torch.bfloat16 — resolved at call time
```

The kernel targets SM80 (`__CUDA_ARCH__ >= 800`) and is verified for correctness on GB200
(SM100) before deployment on A100 (SM80) and RTX 4090 (SM89).

---

## Architecture compatibility

All three SM80 primitives used in the kernel satisfy the `>= 800` guard and have **no
upper-bound restriction** for FP16/BF16 MMA:

| Primitive | Guard | SM80 | SM89 | SM100 |
|---|---|---|---|---|
| `SM80_16x8x16_F32F16F16F32_TN` | `CUTE_ARCH_MMA_SM80_ENABLED` (`>= 800`) | ✓ | ✓ | ✓ |
| `SM80_16x8x16_F32BF16BF16F32_TN` | `CUTE_ARCH_MMA_SM80_ENABLED` (`>= 800`) | ✓ | ✓ | ✓ |
| `SM80_CP_ASYNC_CACHEGLOBAL` | `__CUDA_ARCH__ >= 800` | ✓ | ✓ | ✓ |
| `SM75_U32x4_LDSM_N` | `__CUDA_ARCH__ >= 750` | ✓ | ✓ | ✓ |

The `<= 900` and `<= 890` guards in `mma_sm80.hpp` apply only to B1 (binary 1-bit)
operations — not to FP16/BF16 MMA.

When JIT-compiled on GB200 the compiler uses `--gpu-architecture=sm_100`; `CUTE_ARCH_MMA_SM80_ENABLED`
is satisfied (1000 ≥ 800) and all SM80 tensor-core instructions are valid PTX on SM100.

## Data flow

```
Python call
  asym_gemm.m_grouped_moe_gemm_nt_contiguous(x, w, o, expert_list, index_list)
      │
      ▼
csrc/apis/gemm.hpp
  validate tensors (dtype in {fp16, bf16}, contiguity, shape)
  resolve element_type_str from x.dtype()
  call SM80MoEGemmRuntime::run(args, stream)
      │
      ▼
csrc/jit_kernels/impls/sm80_moe_gemm.hpp
  generate_impl()  →  emit #include + template instantiation string
  Compiler::build() → NVCC JIT-compiles to CUBIN, caches in ~/.asym_gemm/
  launch_impl()    →  load CUBIN, call launch_kernel()
      │
      ▼  kernel runs on GPU
asym_gemm/include/asym_gemm/impls/sm80_moe_gemm.cuh
  sm80_moe_gemm_impl<BLOCK_M, BLOCK_N, BLOCK_K, NWARPS, Element>
    for each expert in expert_list:
        load W tile [BLOCK_N, BLOCK_K] via cp.async
        for each M tile:
            k = 0: load X tile → MMA → write O
            k > 0: load X tile + load prev O → MMA-accumulate → write O
```

## Section 1 — Kernel header (`sm80_moe_gemm.cuh`)

### Template signature

```cpp
template <uint32_t BLOCK_M, uint32_t BLOCK_N, uint32_t BLOCK_K,
          uint32_t NWARPS, typename Element>
__global__ void sm80_moe_gemm_impl(SM80MoEParams params)
```

### Params struct

Raw pointers — no TMA descriptors (SM80 uses `cp.async`, not TMA).  Data pointers are
`void*` so the struct is non-templated and can be passed through the type-erased
`launch_kernel()` boundary.  The kernel casts them to `Element*` at the top of the kernel
body.

```cpp
struct SM80MoEParams {
    void*    x_ptr;        // [total_tokens, K]        row-major — cast to Element* in kernel
    void*    w_ptr;        // [num_experts, N, K]      row-major — cast to Element* in kernel
    void*    o_ptr;        // [total_tokens, N]        row-major — cast to Element* in kernel
    int32_t* expert_list;  // [list_size]  expert IDs
    int32_t* index_list;   // [list_size]  cumulative end token indices
    int32_t  list_size;
    int32_t  expert_size;  // num_experts (W outer stride)
    int64_t  N, K;
};
```

Inside the kernel:
```cpp
auto* x = reinterpret_cast<Element*>(params.x_ptr);
auto* w = reinterpret_cast<Element*>(params.w_ptr);
auto* o = reinterpret_cast<Element*>(params.o_ptr);
```

### Kernel traits (defined inline, no Flash Attention dependency)

```cpp
// MMA atom: FP16 or BF16 16x8x16 tensor core
using MMA_Atom_t = MMA_Atom<std::conditional_t<
    std::is_same_v<Element, cutlass::half_t>,
    SM80_16x8x16_F32F16F16F32_TN,
    SM80_16x8x16_F32BF16BF16F32_TN>>;

using TiledMma = TiledMMA<
    MMA_Atom_t,
    Layout<Shape<Int<NWARPS>, _1, _1>>,
    Tile<Int<16 * NWARPS>, _16, _16>>;

// Shared memory layouts (swizzled, bank-conflict-free)
// SmemLayoutX : [BLOCK_M, BLOCK_K]
// SmemLayoutW : [BLOCK_N, BLOCK_K]
// SmemLayoutO : [BLOCK_M, BLOCK_N]

// Global→smem copy: 128-bit async loads
using GmemCopyAtom = Copy_Atom<SM80_CP_ASYNC_CACHEGLOBAL<uint128_t>, Element>;

// Smem→register copy: LDSM (SM75+)
using SmemCopyAtom = Copy_Atom<SM75_U32x4_LDSM_N, Element>;
```

### Inlined helpers (replaces Flash Attention utilities, ~30 lines total)

- `sm80_cp_async_fence()` — wraps `cute::cp_async_fence()`
- `sm80_cp_async_wait<N>()` — wraps `cute::cp_async_wait<N>()`
- `sm80_copy_g2s<IsEvenMN>(...)` — inline predicated `cute::copy` with out-of-bounds
  zeroing; replaces `FLASH_NAMESPACE::copy<Is_even_MN, ...>`
- `sm80_convert_accum_to_element(tSrO, rO)` — converts FP32 accumulators to `Element`
  register fragment; replaces `flash::convert_type_out`

### Architecture guard

```cpp
#if defined(__CUDA_ARCH__) && __CUDA_ARCH__ >= 800
    // full kernel body
#else
    if (blockIdx.x == 0 && threadIdx.x == 0)
        printf("sm80_moe_gemm requires __CUDA_ARCH__ >= 800\n");
#endif
```

Using `>= 800` (not `== 800`) allows the kernel to compile and run correctly when
JIT-compiled for SM89 or SM100 on the GB200 testbed.

## Section 2 — Heuristics (`csrc/jit_kernels/heuristics/sm80.hpp`)

### Config struct

```cpp
struct SM80GemmConfig {
    uint32_t block_m, block_n, block_k, nwarps;

    int num_threads() const { return nwarps * 32; }

    int smem_bytes() const {
        // sX [BLOCK_M, BLOCK_K] + sW [BLOCK_N, BLOCK_K] + sO [BLOCK_M, BLOCK_N], fp16/bf16
        return int(block_m * block_k + block_n * block_k + block_m * block_n)
               * 2 /* sizeof(fp16 or bf16) */;
    }

    std::pair<int, int> grid_dim(int N) const {
        return {(N + block_n - 1) / block_n, 1};  // one block per N-tile
    }
};
```

### Smem limits and maximum BLOCK_K

With BLOCK_M=128, BLOCK_N=128:

```
smem = (128×BLOCK_K + 128×BLOCK_K + 128×128) × 2
     = 512×BLOCK_K + 32768
```

| Arch | Smem limit | Max BLOCK_K | Smem used |
|---|---|---|---|
| SM80 (A100) | 163,840 B (160 KB) | **256** | 163,840 B |
| SM89 (RTX 4090) | 98,304 B (96 KB) | **128** | 98,304 B |
| SM100 (GB200) | 163,840 B (160 KB) | **256** | 163,840 B |

At BLOCK_K=256 only one block per SM is active. This is the correct trade-off for
MoE GEMM: the kernel is arithmetic-bound per expert, so reducing K-tile loop overhead
outweighs the occupancy cost.

### Selection logic

`block_m=128`, `nwarps=4` are fixed for all SM80-family configs.

```
max_block_k:
  arch == 89  →  128
  else        →  256   # SM80 and SM100

block_k = max_block_k
while K % block_k != 0 and block_k > 16:
    block_k //= 2      # halve until K is divisible; minimum = 16 (MMA k-dim)

block_n:
  largest of {128, 64, 32} that divides N and satisfies smem_bytes() ≤ smem_limit
```

For common production shapes (K = 4096, 7168, 2048) BLOCK_K=256 is selected on
SM80/SM100 and BLOCK_K=128 on SM89. For K < 256, BLOCK_K halves until K is divisible.

Performance note for RTX 4090 (SM89): the heuristic uses the same `block_m` and `nwarps`
but caps `block_k=128` and `smem_limit=96 KB`. When deploying on RTX 4090, an SM89-specific
branch can be added to tune `block_m` and `block_n` for SM89's 128 SMs and 72 MB L2.

## Section 3 — JIT runtime wrapper (`csrc/jit_kernels/impls/sm80_moe_gemm.hpp`)

Mirrors `sm100_bf16_asym_gemm.hpp` but without TMA descriptor arguments.

### Args struct

```cpp
struct Args {
    int n, k;
    SM80GemmConfig gemm_config;
    LaunchArgs launch_args;
    std::string element_type_str;   // "cutlass::half_t" or "cutlass::bfloat16_t"

    // raw device pointers (cast to uint64_t for transport through JIT boundary)
    uint64_t x_ptr, w_ptr, o_ptr;
    uint64_t expert_list_ptr, index_list_ptr;
    int32_t  list_size, expert_size;
};
```

### `generate_impl()`

```cpp
static std::string generate_impl(const Args& args) {
    return fmt::format(R"(
#include <asym_gemm/impls/sm80_moe_gemm.cuh>
using namespace asym_gemm;
static void __instantiate_kernel() {{
    auto ptr = reinterpret_cast<void*>(
        &sm80_moe_gemm_impl<{}, {}, {}, {}, {}>);
}};
)",
        args.gemm_config.block_m,
        args.gemm_config.block_n,
        args.gemm_config.block_k,
        args.gemm_config.nwarps,
        args.element_type_str);
}
```

The JIT cache key incorporates `element_type_str`, so FP16 and BF16 produce separate
CUBINs automatically.

### `launch_impl()`

```cpp
static void launch_impl(const KernelHandle& kernel,
                         const LaunchConfigHandle& config, Args args) {
    // SM80MoEParams uses void* data pointers so this struct is non-templated
    // and matches the kernel's parameter layout regardless of Element type.
    SM80MoEParams params {
        reinterpret_cast<void*>(args.x_ptr),
        reinterpret_cast<void*>(args.w_ptr),
        reinterpret_cast<void*>(args.o_ptr),
        reinterpret_cast<int32_t*>(args.expert_list_ptr),
        reinterpret_cast<int32_t*>(args.index_list_ptr),
        args.list_size, args.expert_size,
        args.n, args.k
    };
    DG_CUDA_UNIFIED_CHECK(launch_kernel(kernel, config, params));
}
```

## Section 4 — Python API (`csrc/apis/gemm.hpp` + `csrc/python_api.cpp`)

### Function signature

```cpp
// csrc/apis/gemm.hpp
void m_grouped_moe_gemm_nt_contiguous(
    torch::Tensor x,            // [total_tokens, K]        fp16 or bf16, contiguous
    torch::Tensor w,            // [num_experts, N, K]      fp16 or bf16, contiguous
    torch::Tensor o,            // [total_tokens, N]        fp16 or bf16, pre-allocated output
    torch::Tensor expert_list,  // [list_size]              int32
    torch::Tensor index_list    // [list_size]              int32 (cumulative end indices)
);
```

### Validation checks

- `x.dtype() == torch::kFloat16 or torch::kBFloat16`
- `w.dtype() == x.dtype()`
- `o.dtype() == x.dtype()`
- All three are contiguous
- `x.dim() == 2`, `w.dim() == 3`, `o.dim() == 2`
- `x.size(1) == w.size(2)` (K matches)
- `w.size(1) == o.size(1)` (N matches)
- `x.size(0) == o.size(0)` (total_tokens matches)
- `expert_list.dtype() == torch::kInt32`
- `index_list.dtype() == torch::kInt32`
- `K % 16 == 0` (MMA k-dim alignment)
- `N % 32 == 0` (minimum block_n)

### Dispatch

```cpp
int N = w.size(1), K = w.size(2);
int arch = device_runtime->get_arch(false, false);  // e.g. 80, 89, 100
auto config = sm80::select_config(N, K, arch);
auto stream = at::cuda::getCurrentCUDAStream().stream();

// Resolve element type from tensor dtype at call time
const std::string element_type_str =
    (x.dtype() == torch::kFloat16) ? "cutlass::half_t" : "cutlass::bfloat16_t";

SM80MoEGemmRuntime::Args args {
    N, K, config,
    LaunchArgs(config.grid_dim(N), config.num_threads(), config.smem_bytes()),
    element_type_str,
    (uint64_t)x.data_ptr(), (uint64_t)w.data_ptr(), (uint64_t)o.data_ptr(),
    (uint64_t)expert_list.data_ptr(), (uint64_t)index_list.data_ptr(),
    (int32_t)expert_list.size(0), (int32_t)w.size(0)
};
SM80MoEGemmRuntime::run(args, stream);
```

## Section 5 — Test file (`tests/test_sm80_moe.py`)

### Reference function

```python
@torch.no_grad()
def ref_moe_gemm(x, w, expert_list, index_list):
    """
    x:           [total_tokens, K]   fp16 or bf16
    w:           [num_experts, N, K] fp16 or bf16
    expert_list: [list_size]         int32
    index_list:  [list_size]         int32 (cumulative end token indices)
    returns:     [total_tokens, N]   fp32
    """
    total_tokens, K = x.shape
    N = w.shape[1]
    out = torch.zeros(total_tokens, N, dtype=torch.float32, device=x.device)
    start = 0
    for i, expert_id in enumerate(expert_list.tolist()):
        end = index_list[i].item()
        out[start:end] = x[start:end].float() @ w[expert_id].float().t()
        start = end
    return out
```

### Test cases

```python
# (num_experts, N, K, token_counts_per_active_expert)
TEST_CASES = [
    # Single BLOCK_K tile (k=0 path only)
    (8,  4096,   256, [12, 8, 20, 28]),
    # Two BLOCK_K tiles (k>0 accumulation path)
    (8,  4096,   512, [128, 64, 256, 12]),
    # 16 tiles — common production shape
    (8,  4096,  4096, [256, 128, 512, 64, 300, 100, 200, 400]),
    # 28 tiles — LLaMA/DeepSeek FFN hidden dim
    (8,  4096,  7168, [128, 256, 64, 192]),
    # K=128 → falls back to BLOCK_K=128 (K < 256)
    (8,  4096,   128, [100, 200, 50, 150]),
    # Large N — exercises block_n=128 heuristic path
    (8, 16384,  4096, [64, 128, 32, 96]),
    # Partial M-tiles — exercises boundary predication in sm80_copy_g2s
    (4,  4096,   256, [7, 13, 31, 127]),
    # Single expert
    (4,  4096,  4096, [512]),
]
```

### Test runner

```python
@torch.no_grad()
def test_moe_gemm(dtype: torch.dtype):
    dtype_str = "fp16" if dtype == torch.float16 else "bf16"
    kernel_fn = asym_gemm.m_grouped_moe_gemm_nt_contiguous

    for (num_experts, N, K, token_counts) in TEST_CASES:
        expert_list_h = list(range(len(token_counts)))
        total_tokens  = sum(token_counts)
        index_list_h  = list(itertools.accumulate(token_counts))

        x           = torch.randn(total_tokens, K,      dtype=dtype,       device='cuda')
        w           = torch.randn(num_experts, N, K,    dtype=dtype,       device='cuda')
        o           = torch.empty(total_tokens, N,      dtype=dtype,       device='cuda')
        expert_list = torch.tensor(expert_list_h,       dtype=torch.int32, device='cuda')
        index_list  = torch.tensor(index_list_h,        dtype=torch.int32, device='cuda')

        kernel_fn(x, w, o, expert_list, index_list)
        ref = ref_moe_gemm(x, w, expert_list, index_list)   # fp32

        diff = calc_diff(o.float(), ref)
        threshold = 0.01
        status = "PASS" if diff < threshold else "FAIL"
        print(f"[{status}] {dtype_str} N={N} K={K} tokens={total_tokens}  diff={diff:.6f}")
        assert diff < threshold, f"Correctness check failed: diff={diff}"

if __name__ == '__main__':
    test_moe_gemm(torch.float16)
    test_moe_gemm(torch.bfloat16)
    print("All tests passed.")
```

### Coverage

| Case | Path exercised |
|---|---|
| `K=256` | k=0 write path only |
| `K=512, 128` | k>0 read-modify-write accumulation |
| `K=4096, 7168` | Many K-tiles, full arithmetic intensity |
| `K=128` | `block_k` halving heuristic |
| `N=16384` | `block_n=128` heuristic path |
| Partial M-tiles | Boundary predication in `sm80_copy_g2s` |
| Single expert | `list_size=1` edge case |

## Implementation order

1. `asym_gemm/include/asym_gemm/impls/sm80_moe_gemm.cuh` — kernel header
2. `csrc/jit_kernels/heuristics/sm80.hpp` — config struct + `select_config()`
3. `csrc/jit_kernels/impls/sm80_moe_gemm.hpp` — JIT runtime wrapper
4. `csrc/apis/gemm.hpp` — add `m_grouped_moe_gemm_nt_contiguous()` (dispatches on dtype)
5. `csrc/python_api.cpp` — register the function
6. `asym_gemm/__init__.py` — export the symbol
7. `tests/test_sm80_moe.py` — correctness test
8. `install.sh` + rebuild — verify JIT cache populates correctly
9. Run `python tests/test_sm80_moe.py` on GB200

## Out of scope (follow-up)

- Double-buffer pipelining (overlap cp.async with MMA)
- SM89-specific heuristic tuning for RTX 4090 performance
- Removal of `mixtureExpertKernel.cu`, `compile.sh`, `test.cpp` (keep until test passes)
