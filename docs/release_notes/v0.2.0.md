# AsymGEMM v0.2.0

**Target Release Date:** July 2026

This release adds SM90 (Hopper) support, INT8 asymmetric GEMM, and a unified CPU + GPU MoE runtime with adaptive dispatch, extending AsymGEMM beyond the SM100/SM89 scope of the initial v0.1.0 release.

---

# Highlights

## SM90 (Hopper) Support

AsymGEMM now runs on Hopper-class GPUs — **H100, H200, H20, and GH200** — with native asymmetric GEMM kernels using TMA + WGMMA over pinned host memory:

- **BF16** asymmetric GEMM (contiguous and masked layouts)
- **FP8 (E4M3)** asymmetric GEMM with 1D×1D block scales
- **INT8** asymmetric GEMM (new in this release, SM90 only)

The architecture-agnostic entry points (`m_grouped_{bf16,fp8,int8}_asym_gemm_nt_{contiguous,masked}`) detect the device architecture at call time and route to the appropriate kernel, so existing SM100/SM89 callers pick up Hopper support without code changes.

---

## INT8 Asymmetric GEMM

New INT8 kernels (SM90) consume `(int8_data, fp32_scale)` pairs with a fixed `(1, 1, 128)` block recipe — per-token scales for activations, per-channel scales for weights — and produce BF16 output.

An offline weight converter, `scripts/convert_int8_weights.py`, quantizes BF16 MoE checkpoints (e.g. the Qwen3 family, including Qwen3.5) to the unified-MoE INT8 format. The offline output is byte-identical to online quantization via `unified_moe.Layer.from_bf16`, and eliminates the per-expert quantization loop that otherwise dominates server startup on large MoE models.

---

## Unified CPU + GPU MoE Runtime

The new `asym_gemm.unified_moe` package (`Layer`, `DispatchModel`) turns the host CPU into a second compute backend rather than just a weight store. Each MoE forward is split into two buckets that execute **concurrently**:

- **CPU bucket** — experts with few routed tokens run on the host via a bundled CPU GEMM library (`csrc/cpu/cpu_gemm`) with AMX INT8/BF16, AVX-512-VNNI INT8, and AVX2 BF16 backends selected at runtime by CPUID probing.
- **GPU bucket** — the remaining experts run on the GPU INT8 path over the same pinned weight bytes.

**Adaptive dispatch** (opt-in via `adaptive=True`): a linear cost model per backend is fitted online from observed timings, and each forward solves for the expert partition that minimizes the predicted makespan of the two buckets. Cost models can be shared across same-shape layers and warm-started across shapes and processes. The default remains the static `m_cpu = 16` threshold. See [`adaptive_dispatch.md`](../../adaptive_dispatch.md) for the design and measured behavior.

## SM89 Improvements

- **BF16** MoE GEMM support on SM89 (Ada Lovelace).
- FP8 kernels accept **native block scales** (1×128 activation, 128×128 weight) in addition to the existing per-tensor and per-token/per-channel scale formats, wired through the arch-agnostic dispatch entry points.

---

### AsymGEMM LoRA SFT

- **SM100 BF16 LoRA SFT as a backend of LLaMA-Factory** — frozen base weights stay in CPU memory and compute through AsymGEMM training kernels, while the LoRA optimizer states are computed in HBM and offloaded to CPU for optimizer updates; trained adapters save and load in the standard PEFT format.
- **Both dense and MoE models** — supports the Qwen3, Qwen3.5, and Llama 4 families, with grouped per-expert LoRA for MoE layers and expert- or data-parallel multi-GPU execution.
- **CPU-offloaded training memory** — activation offload, recompute checkpointing, base-weight paging with optional NVMe spill, and a CPU AdamW optimizer keep weights, gradients, and optimizer state in host memory, enabling long-context fine-tuning of large models on a small number of GPUs.

## Testing and Tooling

- `scripts/test.sh` — arch-aware test runner; sm_90 now runs `tests/test_sm90_int8.py`, and the unified-MoE CPU/GPU parity suite (`tests/test_unified_moe.py`) always runs, skipping internally when the host lacks AMX.
- `scripts/test_cpu_gemm.sh` — standalone CTest suite for the CPU GEMM library.
- New benchmarks: `tests/bench_sm90_int8.py`, `tests/bench_unified_moe.py`; new H20 correctness suites (`tests/test_h20_bf16.py`, `tests/test_h20_fp8.py`).
- Test ground truth now uses pure torch references instead of DeepGEMM, removing it as a test dependency.

# Current Scope and Limitations

- INT8 asymmetric GEMM is currently SM90-only; SM100 and SM89 INT8 support is planned.
- The adaptive dispatcher assigns whole experts; hot-expert row splitting between CPU and GPU is designed but not yet wired into the main runtime.
- CUDA-Graph capture with the unified MoE layer implies an all-GPU partition.
- The current implementation remains primarily optimized for prefill-heavy inference workloads; the CPU bucket of the unified runtime is the first step toward decode-path improvement.
- Comprehensive performance benchmarking across architectures (SM89/SM90/SM100 and the unified CPU + GPU runtime) is planned for the next release.
- This is an internal release intended for evaluation and infrastructure integration.
