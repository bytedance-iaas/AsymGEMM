# AsymGEMM — Initial Internal Release

**Target Release Date:** May 26, 2026

This release introduces the first internal version of AsymGEMM, a CPU-resident MoE execution backend designed for large-scale model inference under limited GPU memory budgets.

---

# Highlights

## Single-GPU Inference for Large MoE Models

AsymGEMM enables inference of extremely large MoE models such as Qwen3.5-397B on a single B200 GPU or Qwen/Qwen3.5-122B-A10B-FP8 on a RTX 4090 by storing MoE weights in CPU DRAM and accessing them on demand through the CPU–GPU interconnect.

This removes the traditional HBM capacity constraint and significantly reduces GPU memory requirements compared with conventional GPU-resident deployments.

---

## Prefill-Oriented Optimization

The current implementation is primarily optimized for:

- Prefill-heavy inference workloads
- Long-context serving
- Fine-tuning and training-related workloads


---

## Broad Hardware Compatibility

Supported platforms include:

- NVIDIA Blackwell-series GPUs
  - e.g. GB200 NVL72
- Consumer GPUs
  - e.g. RTX 4090

This enables deployment across both datacenter-scale and commodity environments.

---

## Precision Support

Supported data types:

- BF16
- FP8
- FP4

Users may trade off model quality, memory footprint, and throughput depending on workload requirements.

---

## Interconnect Support

AsymGEMM supports multiple CPU–GPU interconnect technologies:

- PCIe
- NVLink-C2C

The backend is optimized for high-bandwidth Superchip architectures while remaining functional on standard PCIe systems.

---

# Current Scope and Limitations

- The current release focuses primarily on prefill performance.
- Decode-heavy workloads may not benefit due to CPU→GPU bandwidth overhead.
- Performance characteristics are workload-dependent and sensitive to request concurrency and sequence length distribution.
- This is an internal preview release intended for evaluation and infrastructure integration.
