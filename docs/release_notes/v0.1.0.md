# AsymGEMM — Initial Internal Release

**Target Release Date:** May 27, 2026

This release introduces the first internal version of AsymGEMM, a CPU-resident MoE execution backend designed for large-scale model inference under limited GPU memory budgets.

---

# Highlights

## Reduced GPU Requirements for Large MoE Models

AsymGEMM reduces the number of GPUs needed to serve large MoE models by storing MoE weights in CPU DRAM and accessing them on demand through the CPU–GPU interconnect. For example, Qwen3.5-397B can run on a single B200 GPU, and Qwen/Qwen3.5-122B-A10B-FP8 on a single RTX 4090 — deployments that would otherwise require multiple GPUs.

---

## Hardware Support

AsymGEMM currently supports two NVIDIA GPU architectures:

- **SM100** (Blackwell) — with NVLink-C2C and PCIe interconnects
- **SM89** (Ada Lovelace) — with PCIe interconnect

---

## Precision Support

Supported data types:

- BF16
- FP8
- FP4

Users may trade off model quality, memory footprint, and throughput depending on workload requirements.

---

# Current Scope and Limitations

- The current implementation is primarily optimized for prefill-heavy inference workloads.
- Decode-heavy workloads may not benefit due to CPU→GPU bandwidth overhead.
- This is an internal preview release intended for evaluation and infrastructure integration. Additional optimizations, expanded model coverage, and decode-path improvements are under active development.
