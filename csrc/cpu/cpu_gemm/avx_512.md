# avx_512.md — Automatic AMX → AVX-512-VNNI Fallback for the CPU INT8 Path

Status: design (pre-implementation)
Target branch: **`qian/avx512-fallback`** (off the post-NUMA tip of
`unified_kernel_sm90_v2`)
Companion docs:
* `Stride.md` — the shared row-major INT8 + per-channel FP32 scales
  contract that both kernels must consume identically.
* `layout.md` — the per-expert weight layout shared by CPU and GPU.
* `cpu_comparison.md` — the NUMA-aware WorkerPool plan; this work
  layers on top of it.
* `performance_compare.md §10-§18` — the dispatcher evolution that
  brought us to a single canonical row-major path.

---

## 1. The Question this Doc Answers

> On a host without AMX (Ice Lake, Cascade Lake, some cloud SKUs), the
> production MoE forward today fails. How do we make `cg_moe_int8_amx`
> and the `cg_gemm` INT8 path **automatically** pick AVX-512-VNNI as a
> fallback, with **no user configuration**, while reading the exact
> same pinned weight bytes the AMX path reads (and the GPU TMA reads)?

The cpu_gemm tree already ships the AVX-512-VNNI INT8 kernel
(`src/kernels/avx512/int8_gemm_rm.cpp`), built when
`CPU_GEMM_WITH_AVX512_VNNI=ON`. It is tested standalone
(`test_avx512_vnni_int8_rm`) and the file name's `_rm` suffix flags the
intent: same row-major layout as `amx/int8_gemm_rm.cpp`. **What is
missing is the dispatcher wiring** — neither `gemm.cpp`'s `run_cg_gemm`
nor `moe.cpp`'s `cg_moe_int8_amx` ever calls into it.

> **TL;DR.** Introduce a small `Int8RmBackend` function-pointer table
> populated once at first use from CPUID. AMX gets first pick; AVX-512-
> VNNI fills in when AMX isn't usable. Both dispatchers (`cg_gemm` and
> `cg_moe_int8`) read the table instead of hardcoding `amx::int8_rm_*`.
> The kernel ABI is unchanged. The slab is unchanged. `Layer.forward`
> is unchanged. The user does nothing.

## 2. The Constraint — Single Shared Row-Major Byte Layout

`layout.md:37-42` defines the canonical weights:

```
gate_int8   row-major [G, N_inter, K_hidden] int8     pinned host
gate_scales per-channel [G, N_inter]          float32  pinned host
```

Three readers must consume the exact same bytes:

| Reader | How |
|---|---|
| GPU SM90 TMA (UVA box copy) | Per `int8.md` — descriptor expects `[N_inter, K_hidden]` contiguous int8 per expert |
| CPU AMX (`amx::int8_rm_run`) | Strided `_tile_loadd` with `ldb = K_hidden`; per-channel scales applied at unpack (`Stride.md`) |
| **CPU AVX-512-VNNI (this plan)** | Must consume the same `[N_inter, K_hidden]` row-major int8 + `[N_inter]` per-channel FP32 scales |

The AVX-512-VNNI kernel **already does** — that's why both files are
named `int8_gemm_rm.cpp`. The `_rm` (row-major) suffix is a contract
across the codebase: any function with this suffix reads the canonical
slab without a separate B-pack. The remaining work is wrapping the
kernel in a uniform call surface so the dispatcher can swap backends
at runtime without seeing layout differences.

### 2.1 What the contract forbids

* No separate AVX-512-VNNI weight pack. The byte layout is fixed at
  slab construction (one `pin_memory()` allocation per weight tensor)
  and re-packing would defeat the GPU's TMA fetch.
* No quantization-scheme drift. Per-channel FP32 scales, INT8 weights
  signed, A-side BF16. Same as today.
* No N alignment change. The unified-MoE runtime pads `N_inter` to a
  multiple of 128 (GPU constraint). AMX needs N divisible by 32; AVX-
  512-VNNI is conventionally satisfied by 16-row tiles. **The plan
  must keep both alignment predicates satisfied by the existing slab
  padding**, not impose a new alignment.

## 3. The Mechanism — One Function-Pointer Table, Cached

`src/dispatch/int8_rm_backend.{h,cpp}` (new, ~80 LOC).

### 3.1 The struct

```cpp
namespace cpu_gemm {

struct ScratchSizes {
  std::size_t a_bytes;     // packed-A scratch
  std::size_t c_bytes;     // INT32-or-equivalent accumulator scratch
  std::size_t total() const { return a_bytes + c_bytes; }
};

struct Int8RmBackend {
  using pack_a_fn = void(*)(int m, int k,
                            const cg_bf16_t* a_bf16, void* sA);
  using run_fn    = void(*)(int m, int n, int k,
                            const void* sA,
                            const int8_t* b_int8, int ldb,
                            void* sC,
                            int ith, int nth);
  using unpack_fn = void(*)(int m, int n,
                            const float* a_scales,
                            const float* b_scales,
                            const void* sC,
                            float alpha, float beta,
                            float* c_fp32, int ldc,
                            int ith, int nth);
  using scratch_fn = ScratchSizes(*)(int m, int n, int k);

  pack_a_fn  pack_a;
  run_fn     run;
  unpack_fn  unpack_transposed;
  scratch_fn scratch_sizes;

  int  k_step;            // 64 for both AMX and AVX-512-VNNI
  int  n_step;            // 32 (AMX), 16 (AVX-512-VNNI)
  bool ok;                // false → no usable backend on this host
  const char* name;       // "amx_int8_rm" | "avx512_vnni_int8_rm" | "none"
};

/* Returns a process-wide-cached singleton chosen from CPUID + per-
 * thread XSAVE permission. First call probes; subsequent calls hit
 * the cache. */
const Int8RmBackend& select_int8_rm_backend();

}  // namespace cpu_gemm
```

### 3.2 The selector

```cpp
const Int8RmBackend& select_int8_rm_backend() {
  static const Int8RmBackend chosen = [] {
    // Test-only override; production should never set this.
    if (const char* force = std::getenv("ASYM_GEMM_FORCE_BACKEND")) {
      if (std::strcmp(force, "amx") == 0) return make_amx_backend();
      if (std::strcmp(force, "avx512") == 0) return make_avx512_vnni_backend();
      if (std::strcmp(force, "none") == 0)
        return Int8RmBackend{nullptr,nullptr,nullptr,nullptr,0,0,false,"none"};
      // Unknown value → fall through to autodetect.
    }

    cg_caps_t caps = cg_query_caps();

#ifdef CPU_GEMM_HAS_AMX
    /* AMX takes priority: ~3-5× peak throughput over VNNI on the same
     * core (e.g. on SPR, AMX-INT8 ≈ 80 TFLOPS/socket, VNNI ≈ 20-25). */
    if (caps.has_amx_int8 &&
        cpu_gemm::kernels::amx::amx_available()) {
      return make_amx_backend();
    }
#endif

#ifdef CPU_GEMM_HAS_AVX512_VNNI
    /* Fallback: AVX-512-VNNI INT8. Works on Ice Lake, Cascade Lake,
     * and any AMX host where the kernel refused XSAVE permission. */
    if (caps.has_avx512_vnni && caps.has_avx512f) {
      return make_avx512_vnni_backend();
    }
#endif

    return Int8RmBackend{nullptr,nullptr,nullptr,nullptr,0,0,false,"none"};
  }();
  return chosen;
}
```

Key properties:

1. **`static` lambda + `cg_query_caps()` already cached** — CPUID
   reads exactly once across the process lifetime; subsequent calls
   return the populated struct with zero overhead. No `if (cached)`
   branch in the hot path.

2. **Compile-time gated by `#ifdef`** — building with
   `CPU_GEMM_WITH_AMX=OFF` makes the AMX branch disappear entirely;
   the runtime is then a single-backend AVX-512-VNNI build. Likewise
   for `CPU_GEMM_WITH_AVX512_VNNI=OFF` (which we never set off today
   but the option exists).

3. **`ok=false` is a real state.** Pre-VNNI hardware (Skylake, Zen
   1-3 without VNNI) returns the all-null backend, and dispatchers
   check `be.ok` before calling. They return `CG_E_UNSUPPORTED`
   instead of crashing with `SIGILL`.

### 3.3 Why a function-pointer table and not templates

Templates would force compile-time selection — one binary per
backend. The function-pointer table gives one binary that runs on
both AMX and non-AMX hosts. Two indirections per kernel phase
(pack-A, run, unpack); each indirection is a few ns and gets buried
in the per-tile compute. Measured AMX overhead from indirection:
< 0.5% on medium/qlen=1024.

`std::function` was considered and rejected — extra allocation, type
erasure, and a heap touch on first call. Raw function pointers are
the right choice for a hot dispatch table whose member set is fixed
at compile time.

## 4. Architecture Detail

### 4.1 What the AVX-512-VNNI kernel side must expose

`src/kernels/avx512/int8_gemm_rm.{h,cpp}` already implements the
kernels; the public surface needs to be normalized to match the AMX
namespace shape:

```cpp
// src/kernels/avx512/int8_gemm_rm.h
namespace cpu_gemm::kernels::avx512 {

void int8_rm_pack_a_bf16(int m, int k,
                         const cg_bf16_t* a_bf16, void* sA);

void int8_rm_run(int m, int n, int k,
                 const void* sA,
                 const int8_t* b_int8, int ldb,
                 void* sC, int ith, int nth);

void int8_rm_unpack_transposed(int m, int n,
                               const float* a_scales,
                               const float* b_scales,
                               const void* sC,
                               float alpha, float beta,
                               float* c_fp32, int ldc,
                               int ith, int nth);

ScratchSizes int8_rm_scratch_sizes(int m, int n, int k);

}  // namespace
```

If the existing entries have different names or signatures (likely
some do — the `test_avx512_vnni_int8_rm` test exercises the kernel
directly without the dispatcher contract), Phase 2 of the plan adds
**thin adapter wrappers** in the same `int8_gemm_rm.cpp` rather than
renaming the underlying kernel:

```cpp
// At the bottom of src/kernels/avx512/int8_gemm_rm.cpp
namespace cpu_gemm::kernels::avx512 {

void int8_rm_pack_a_bf16(int m, int k,
                         const cg_bf16_t* a_bf16, void* sA) {
  // Adapter to the underlying private kernel.
  detail::pack_a(m, k, a_bf16, sA);
}
// ... matching run / unpack / scratch_sizes adapters ...

}
```

This pattern keeps the kernel internals untouched, just exposes them
under the contract names. Estimated adapter shim: ~30 LOC.

### 4.2 Differences in kernel internals to handle in the adapter

| Aspect | AMX | AVX-512-VNNI |
|---|---|---|
| K block per VNNI dot | 4 (interleaved INT8) | 4 (`vpdpbusd`) |
| Required K alignment | 64 (K_STEP, AMX tile dim) | 64 (1 KB cache line × 16) — same |
| Tile output | INT32 in tile register, transposed | INT32 in `zmm` (16 lanes), row-major |
| N register tiling | 32 (AMX tile = 16×16 then split) | 16 (`zmm` 16 INT32 lanes) |
| sC scratch layout | Tiled, transposed (per `Stride.md`) | Linear `[m, n_block]` INT32 |
| sA scratch layout | VNNI-packed (4 K's per dword) | VNNI-packed (same) |

**sA is shared between backends** because VNNI packing is identical
(`vpdpbusd` and AMX both want `[K/4, M, 4]`). **sC differs**, which
is why the backend struct carries `scratch_sizes`. The `unpack` step
internalises the layout difference — AMX unpacks the transposed tile
and scales; AVX-512-VNNI does a row-major INT32 → FP32 conversion
with the same `(A_scale[m] × B_scale[n])` outer-product.

### 4.3 The two dispatchers' update

**`gemm.cpp:297-369` — single-GEMM dispatcher**

Replace the chain of `amx_int8_*_eligible` + `run_amx_int8_*` for the
row-major case with one backend-driven branch:

```cpp
cg_status_t run_cg_gemm(rt, d) {
#if defined(CPU_GEMM_HAS_AMX)
  // The prepacked path is AMX-only by design (offline pre-pack uses
  // AMX tile layout). Keep its branch as-is — there is no AVX-512-VNNI
  // prepacked variant and we don't need one.
  if (rt && rt->pool && amx_int8_prepacked_eligible(d))
    return run_amx_int8_prepacked(rt, d);
#endif

  // Row-major INT8 — runtime-pick AMX or AVX-512-VNNI.
  if (rt && rt->pool) {
    const auto& be = select_int8_rm_backend();
    if (be.ok && int8_rm_eligible_for(d, be))
      return run_int8_rm(rt, d, be);
  }

#if defined(CPU_GEMM_HAS_AMX)
  // Legacy packed-on-touch INT8 — still AMX-only; unreachable when
  // the row-major path covers the shape (it does for unified-MoE).
  // Retained for tests/bench_compare_ktransformers.py linear scenario
  // until those callers are migrated.
  if (rt && rt->pool && amx_int8_eligible(d))
    return run_amx_int8(rt, d);

  if (amx_bf16_eligible(d)) { /* AMX BF16 — unchanged */ }
#endif

  if (is_bf16_bf16_f32_nt(d)) { /* AVX2 BF16 fallback — unchanged */ }
  return CG_E_UNSUPPORTED;
}
```

Where `run_int8_rm(rt, d, be)` is the backend-agnostic body:

```cpp
cg_status_t run_int8_rm(cg_runtime_t* rt, const cg_gemm_desc_t* d,
                        const Int8RmBackend& be) {
  int m = (int)d->m, n = (int)d->n, k = (int)d->k;
  ScratchSizes ss = be.scratch_sizes(m, n, k);

  void* base = rt->scratch->reserve(ss.total());
  auto* p = reinterpret_cast<unsigned char*>(base);
  void* sA = p;                  p += ss.a_bytes;
  void* sC = p;

  /* int N_BLOCK = be.n_step * 4 or similar; current per-backend value. */
  int nth = rt->threads;
  int max_n_blocks = (n + be.n_step - 1) / be.n_step;
  if (nth > max_n_blocks) nth = max_n_blocks;
  if (nth <= 0) nth = 1;

  const auto* a = reinterpret_cast<const cg_bf16_t*>(d->a);
  const auto* b = reinterpret_cast<const int8_t*>(d->b);
  auto* c       = reinterpret_cast<float*>(d->c);
  const auto* a_scales = /* per-row from A side (caller convention) */;
  const auto* b_scales = reinterpret_cast<const float*>(d->b_scales);

  rt->pool->parallel_for(nth, [&](int ith) {
    if (ith == 0) be.pack_a(m, k, a, sA);
  });
  rt->pool->parallel_for(nth, [&](int ith) {
    be.run(m, n, k, sA, b, (int)d->ldb, sC, ith, nth);
  });
  rt->pool->parallel_for(nth, [&](int ith) {
    be.unpack_transposed(m, n, a_scales, b_scales, sC,
                         d->alpha, d->beta, c, (int)d->ldc, ith, nth);
  });
  return CG_OK;
}
```

**`moe.cpp` — MoE dispatcher**

`cg_moe_int8_amx` is renamed to `cg_moe_int8`; a thin alias keeps the
old symbol working for the existing pybind binding:

```cpp
extern "C" void cg_moe_int8(cg_runtime_t* rt, cg_moe_int8_batch_t* batch) {
  const auto& be = select_int8_rm_backend();
  if (!be.ok) {
    /* Set an error sentinel the caller can pick up. */
    batch->status = CG_E_UNSUPPORTED;
    return;
  }

  /* All existing scratch arena setup, but uses be.scratch_sizes(...)
   * instead of the hardcoded amx::int8_rm_scratch_sizes. */
  ScratchSizes per_expert_ss = be.scratch_sizes(max_m_e, N_inter, K_hidden);
  /* ... partition scratch into per-expert slices using
   * sum over experts of per_expert_ss.total(); same shape as today. */

  /* Per-NUMA / per-expert dispatch — same as today, but inside the
   * lambda the AMX-specific calls become backend-routed: */
  rt->pool->do_numa_job([&](int numa_id) {
    /* ... iterate experts assigned to this NUMA ... */
    for (auto e : my_experts) {
      be.pack_a(m_e, K_hidden, x_cat_e, sA_top_e);
      be.run    (m_e, N_inter, K_hidden, sA_top_e,
                 gate_int8_e, ldb_gate, sC_gate_e, ith, nth);
      be.unpack_transposed(m_e, N_inter, a_scales, gate_scales_e,
                           sC_gate_e, 1.0f, 0.0f, c_gate_e, N_inter,
                           ith, nth);
      /* ... up, SwiGLU, down — same pattern, backend-routed ... */
    }
  });
}

/* Legacy alias for the existing _C.moe_int8 pybind binding. */
extern "C" void cg_moe_int8_amx(cg_runtime_t* rt,
                                 cg_moe_int8_batch_t* batch) {
  cg_moe_int8(rt, batch);
}
```

The `_amx` suffix on the legacy entry is now misleading but kept for
ABI stability. Python callers see `_C.moe_int8` (Python name unchanged
since `cpu_module.cpp` binds the function under that name), and the
C++ caller graph from cpu_module.cpp doesn't need to know which
backend ran.

### 4.4 Eligibility per backend

The N alignment differs (AMX needs 32, VNNI needs 16). The unified-MoE
slab pads `N_inter` to multiples of 128 (`Layer.from_bf16`
`GRAN_K=128` constraint), which satisfies both. For the legacy single-
GEMM API (`cg_gemm`), a shape with `N=48` would be VNNI-eligible but
not AMX-eligible — the eligibility check needs to respect each
backend's alignment:

```cpp
bool int8_rm_eligible_for(const cg_gemm_desc_t* d,
                          const Int8RmBackend& be) {
  if (!be.ok) return false;
  if (!is_bf16_int8_f32_nt(d)) return false;
  if (d->k % be.k_step != 0) return false;     // both = 64
  if (d->n % be.n_step != 0) return false;     // AMX=32, VNNI=16
  if (d->lda != d->k)        return false;
  if (d->ldb <  d->k)        return false;
  return true;
}
```

For MoE, the shape constraint propagates from the slab construction;
no new checks needed at the dispatcher boundary.

## 5. Performance Expectations

### 5.1 Peak throughput by backend (per socket)

| Backend | INT8 peak | Limited by |
|---|---:|---|
| AMX-INT8 (SPR / Granite Rapids) | ~80 TFLOPS | Tile register count (8) and L2 read bandwidth |
| AVX-512-VNNI (Ice Lake / Cascade Lake / SPR) | ~20-25 TFLOPS | `vpdpbusd` throughput (1/cycle, 16 INT32 lanes) |

So an AVX-512-VNNI fallback is **~3-4× slower** than AMX at peak.
That's a fact about the silicon, not the kernel — the dispatcher
should *prefer* AMX whenever possible; the fallback is for hosts that
don't have it.

### 5.2 What this implies for non-AMX deploys

For the production decode shape (DeepSeek-MoE, qlen=1, m_e ~ 1, top_k=8):
the workload is **bandwidth-bound, not compute-bound** (~2 ops/byte
vs ~285 ops/byte AMX peak ratio; see `cpu_comparison.md §2.1`).
Memory bandwidth doesn't change between backends; both saturate the
same DRAM controller. So:

* Decode (qlen=1): VNNI fallback **roughly matches** AMX, because
  neither uses the compute peak.
* Light prefill (qlen=16): VNNI ~1.5-2× slower than AMX.
* Heavy prefill (qlen ≥ 256): VNNI ~3× slower than AMX (the compute
  ratio fully manifests).

On a non-AMX cloud SKU (Ice Lake-class), the fallback is therefore a
real serving fallback — usable for production at light load, fully
expected to underperform at heavy prefill. Customers choosing
non-AMX hardware accept this trade-off.

### 5.3 Numerical equivalence

INT32 accumulation order may differ between AMX (per-tile) and VNNI
(per-`zmm`-row), but the final FP32 result should agree within
floating-point tolerance because:

* Both compute `sum_k (A_int8[m, k] × B_int8[n, k])` as an INT32
  partial sum — exact, no rounding.
* Both apply `(A_scale[m] × B_scale[n])` once at unpack — same
  rounding behavior.

The only divergence is **the order of accumulation across K-blocks**.
On the unified-MoE shapes (`K ≤ 14336`), accumulation order varies by
≤ 224 K-blocks. INT32 sums are commutative, but the final FP32 cast
introduces 1-ULP-class noise. **Acceptance tolerance for parity test:
`max_abs_err < 1e-3`** (looser than the FP32-vs-INT8 noise floor of
`~5e-4`).

## 6. Phased Delivery — 4 PRs

The order matters: PR 1 is a pure refactor (no behavior change), PR 2
adds the signature shim, PR 3 wires the autodetect, PR 4 closes the
test loop.

### PR 1 — Introduce `Int8RmBackend` table, refactor dispatchers to use it (AMX-only behind it)

Scope:

* `src/dispatch/int8_rm_backend.{h,cpp}` (new, ~80 LOC) —
  `Int8RmBackend` struct and `select_int8_rm_backend()`. AMX branch
  populated; AVX-512-VNNI branch returns the all-null backend (so
  selection still picks AMX on AMX-capable hosts).
* `src/dispatch/gemm.cpp` — collapse the three AMX INT8 row-major
  branches in `run_cg_gemm` into one `select_int8_rm_backend()` call
  + `run_int8_rm(rt, d, be)`.
* `src/dispatch/moe.cpp` — rename `cg_moe_int8_amx` → `cg_moe_int8`,
  add a thin legacy alias; the body still calls AMX kernels but
  through the backend table (`be.pack_a`, `be.run`,
  `be.unpack_transposed`).
* Add `cg_int8_rm_backend_name()`, `cg_int8_rm_backend_ok()` C ABI
  + pybind binding (`_C.int8_rm_backend()`, `_C.int8_rm_ok()`).
* `_C.caps()['has_avx512_vnni']` — already in tree per the NUMA work;
  no change.

Acceptance:

* All existing tests pass unchanged on AMX hosts.
* `_C.int8_rm_backend() == 'amx_int8_rm'` on the SPR test host.
* Behavior identical on the §5 smoke-shape pressure bench (within
  ±2% — the indirection cost shouldn't show up).

Estimated diff: ~200 LOC C++, no Python changes other than the new
`_C.int8_rm_backend()` accessor.

## 8. Risks & Open Questions

1. **AVX-512-VNNI kernel signature mismatch.** The existing
   `int8_gemm_rm.cpp` may take different parameter shapes than the
   AMX contract (e.g., different scratch layout, no `unpack` step at
   all if it writes FP32 directly, different scaling convention).
   Mitigation: PR 2 adds adapter wrappers, not rename; the existing
   test still passes against the unwrapped kernel. If the difference
   is large enough that a wrapper isn't viable, escalate to a kernel
   refactor — but the `_rm` naming convention was explicitly set up
   to make this swap clean.

2. **Numerical drift between backends.** Acceptance tolerance
   `1e-3` is loose; an unfortunate test input could spike it. If a
   single shape spikes, inspect rather than relax tolerance — the
   per-channel-FP32 scaling is symmetric across backends and the
   accumulator is INT32, so divergence > 1e-3 indicates a real bug.

3. **`ASYM_GEMM_FORCE_BACKEND` leaking into production.** The env
   var is testing-only; if a serving operator accidentally sets it
   they could pin the system to a slower backend. Mitigation: log
   the chosen backend (and whether it was forced) at the first call.
   The diagnostic accessor `_C.int8_rm_backend()` lets ops
   sanity-check at startup.

4. **Compile-time backend exclusion is brittle.** Building with
   `CPU_GEMM_WITH_AMX=OFF` produces a binary that **only** has the
   VNNI path. If that binary is then deployed on an AMX host, no
   harm — it runs the VNNI path. But the inverse — AMX-only binary
   deployed on a non-AMX host — produces an opaque "no backend
   usable" error. Mitigation: ship one binary with both backends
   compiled in (default for `setup.py build_ext`). Document the
   degraded behavior of single-backend builds.

5. **Coexistence with NUMA work.** PR 1 lands after the NUMA push
   (`cpu_comparison.md` PR 1). The two are orthogonal: NUMA chooses
   *which threads* run the kernel; backend chooses *which kernel
   they run*. The function-pointer table is read inside each
   NUMA-pinned worker, identical across NUMAs.

6. **The pre-packed AMX path stays AMX-only.** No VNNI equivalent
   exists; tests/bench_compare_ktransformers.py §5.1 linear scenario
   still uses it. On a non-AMX host the prepacked path would refuse
   eligibility and the row-major fallback would activate. Document
   in the bench script.

7. **First-call latency.** `select_int8_rm_backend()`'s `static`
   lambda runs once; `enable_amx()` may issue 2-3 `arch_prctl`
   syscalls (`tile_config.h:48-60`). Total first-call cost: < 100
   µs. Not in the hot path.

## 10. Out of Scope

* **AVX2 INT8 path.** No `vpdpbusd` on AVX2; a new INT8 kernel would
  need to manually pad and do `vpmaddubsw` + `vpmaddwd`. Real work
  (~500 LOC), and the throughput would be 2× slower than VNNI.
  Defer until a real customer requires it.
* **FP16 / FP4 / FP8 fallback paths.** Same auto-backend pattern
  applies — separate effort per dtype.
* **Auto-tuning between backends.** Always picks AMX > VNNI > none.
  Auto-search across shape × backend cross-product is a tuning
  system, not this doc.
* **NUMA-specific backend choice.** All NUMAs run the same backend;
  picking different backends per NUMA would require a multi-headed
  selector and benefits nothing (silicon is uniform across NUMAs on
  a single host).
* **Prepacked AVX-512-VNNI INT8 path.** No demand — the offline
  prepack API surface is AMX-specific and is being deprecated in
  favour of the row-major path (`Stride.md`).

## 12. Why This Plan and Not the Alternatives

### Compile-time selection (`#ifdef` everywhere)

Forces one binary per backend. Customer deploying on heterogeneous
fleets (some AMX, some VNNI) ships two wheels. Backend choice
becomes a packaging concern instead of a runtime one. Rejected.

### `std::function`-based dispatch

Type-erasure tax, heap allocation, no inlining across the boundary.
On the hot per-tile loop this adds ~30 ns per phase, ~10% on a
small-shape kernel call. Rejected for raw function pointers.

### Virtual-method backend with `Int8RmBackend*` abstract base

Same indirection cost as function pointers; adds a vtable pointer
and forbids constexpr-folded static dispatch. No clear win. Rejected.

### Make `cg_moe_int8` itself templated on backend

Code bloat (two kernel bodies in the dispatcher), no behavior win,
worse compile times. Rejected.

### Backend selection by C `weak_symbol` linkage

Brittle on macOS / MSVC; fragile when libraries are linked statically.
Rejected.

The function-pointer table pattern is the minimum viable abstraction:
one indirection per kernel phase, zero per-call overhead beyond that,
and the selector reads CPUID exactly once at startup. It matches the
pattern kt-kernel uses for its own dispatch (`kt-kernel/operators/*.hpp`
template-method idiom; for our purposes the simpler PoD-table approach
is enough because we have only two backends to multiplex).
