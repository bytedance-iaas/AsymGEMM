# GB200 multi-GPU design for AsymGEMM LoRA SFT

## Requirements (fixed)
R1. AsymGEMM-native (extends our streaming kernels, not generic systems glue).
R2. GB200-specific (not reproducible on any-NVLink cluster; exploits 2 GPUs : 1 Grace).
R3. Beats hardware-agnostic extension (DeepSpeed ZeRO / Ulysses SP / TP / PP / EP as-is).
R4. Compatible with recomp-off-full-fg (recompute + fine-grained act offload + CPU elementwise).
R5. One-sentence policy, SuperOffload-style; concrete measurable training benefits.
R6. Multi-GPU story distinct from the single-GPU (zero-residency) story.

## Hardware facts (our node, measured)
- Per GPU: own C2C lane ~225 GB/s/dir spec, ~195 H2D measured; lanes independent per GPU and per direction.
- Shared per superchip: one Grace, 480 GB LPDDR5X @ ~500 GB/s, 72 cores. Remote-socket path ~117 GB/s (never use; NUMA-bind).
- GPU<->GPU NVLink ~900 GB/s/dir (4x a C2C lane; on GH200 it was <=1x).
- B200 ~2.3x H100 FLOPs; 189 GB HBM. GH200 gave 450 GB/s/dir C2C to ONE GPU -> per-GPU lane halved, CPU side shared.

## Converged design: sTP (streamed tensor parallelism)

**Policy (one sentence):** On GB200 two GPUs share one Grace, so replicated SP double-streams every frozen byte over two halved C2C lanes, while classic TP — whose shards are naturally disjoint — is unusable because it requires weights resident in HBM; AsymGEMM removes exactly that blocker, so we run **tensor parallelism whose weight shards never exist in HBM**: one copy of the frozen model in the shared Grace arena, each GPU streams its own shard's tiles over its own C2C lane — every byte stored once, read once, lanes disjoint by construction — with each streamed GEMM output-split along the dimension that shards its CPU-resident operand.

**Mutual enablement (the claim):** AsymGEMM removes TP's blocker (HBM residency); TP removes AsymGEMM's multi-GPU blocker (duplicate streams). Neither side is new alone; the composition is, and it only makes sense on GB200 (R2 check below).

**Mapping (dense layer):**
- Attention: head-split (Megatron TP). QKV/O weights column/row-split -> each GPU streams disjoint W tiles from the one arena (different tile offsets into the SAME host buffer — no per-rank host shards). No Ulysses a2a; comm = standard TP AG/RS on X and attn-out over NVLink.
- MLP: gate/up column-split, down row-split (partial-sum epilogue already exists: TMA_REDUCE_ADD). S_gate/S_up are column-sharded [M, F/2] per GPU -> act offload + CPU SiLU are private, disjoint, cores split 36/36.
- Residual stream: Megatron-SP style sequence-shard between TP regions -> total activation memory ~halved.
- MoE: EP (experts disjoint per GPU, existing kerNNN routed kernels unchanged); token a2a on NVLink.
- LoRA: B split with W; A replicated; dS allreduce is tiny (M x r).

**Per-GEMM split rule (AsymGEMM-native core):** every streamed GEMM is output-split along the shard dim of its CPU-resident operand:
- weight-streaming GEMMs (fwd base, bwd dX): split = TP dim of W -> disjoint W tiles per lane.
- activation-streaming GEMMs (bwd LoRA-A grad dA = dS^T @^ X_cpu — our measured #1 bottleneck): split dA by K -> each GPU streams X[:, its K-half] — disjoint X tiles per lane, dS (tiny) replicated. => the bottleneck kernel's delivery doubles too.

**Superchip runtime (kept from earlier iterations):** one process, both GPUs; one pinned arena (weights once + both act pools + NVMe spill); DRAM token-bucket scheduler (weight reads + act traffic + CPU ops <= ~500 GB/s); NUMA membind; per-op placement (GPU-recompute vs CPU-execute vs offload-restream) re-solved with GB200 constants (195/900/500, 36 cores/GPU, 2.3x FLOPs) — GH200-optimal choices flip.

## Why it beats each baseline
| Baseline | Fails because | sTP |
|---|---|---|
| Ulysses SP + per-rank streaming | duplicate weight bytes: stream time unchanged by GPU#2; 2x host | disjoint bytes: delivery 2x (390 vs 195); 1 host copy |
| ZeRO-3 offload_param + Ulysses | per-module allgather INTO both HBMs; no working-activation path (OOM s10-20k vs our s25-45k, 1 GPU) | zero residency kept; activations streamed; no collective on weight path |
| Classic TP-2 | W/2 must be HBM-resident (235B: 235>189 GB dead); burns HBM long-seq needs | shards streamed, never resident; HBM all for activations |
| PP-2 | weights re-streamed x microbatches, or 50% bubble; seq unsharded | weights streamed once/step; act memory halved |
| SuperOffload additions | optimizer tricks inert in LoRA (opt ~0.1s of 100-400s); multi-GPU is stock (Megatron diff = 2 lines; both ranks' CPUAdam pinned to same cores 4-71, stage3.py:205; no membind, numa.py:128) | targets the actual transfer-bound path |

## R2 check — why GB200-only
- Needs operand streaming at GEMM speed: C2C-class link (PCIe 30-55 GB/s is 10-30x short) -> superchips only.
- Needs both GPUs' streams from ONE memory: only exists at 2 GPUs : 1 Grace. On 2x GH200, TP halves come from two DRAMs: no shared arena, and inter-GH200 NVLink (<= C2C) makes TP collectives costly; on GB200 NVLink is 4x C2C -> AG/RS hide under streams.
- Lane arithmetic balances only here: 2 x 195 disjoint = 390 aggregate ~= what one 500 GB/s DRAM can feed with act headroom.

## Claims (measurable)
C1. Weight-delivery + bottleneck-kernel (LoRA-A grad) stream time ~halves (195 -> ~350-390 GB/s effective; DRAM-capped, claim 1.5-2x).
C2. Max seq ~2x single-GPU asym at equal per-GPU HBM (TP+seq-shard halve activations); vs ZeRO-3+Ulysses: 2-3x (their gather windows + unstreamed working set).
C3. Host: one arena => 235B-class bf16 (470 GB) trainable on ONE superchip; per-rank designs need 2x copies or HBM shards — both impossible.
C4. No contention collapse: scheduler keeps combined demand < 500 (motivation fig: nsys of baseline showing duplicate H2D streams + idle NVLink + DRAM oversubscription).

## Risks / open
- TP comm (AG/RS) scales with seq like Ulysses a2a; ~10%/layer at s25k, overlappable — measure early.
- TP degree capped by KV heads (fine at 2); >2 GPUs = sTP intra-superchip x SP/DP across superchips (hierarchy matches hardware).
- MoE expert imbalance -> EP standard problem; credit fallback: any starved GPU streams any tile directly (never below 195).
- Single-process dual-GPU runtime is new plumbing (device loops, streams); collectives via NCCL-in-process or P2P copies (TP-2 AG/RS = one peer copy each).

## Related work check (searched 2026-07)
- SuperOffload (arXiv 2509.21271): ZeRO-3-based, 1 GPU:1 Grace assumed, multi-GPU = stock ZeRO/Ulysses. No TP, no streaming GEMMs.
- TensorRT-LLM weight streaming: inference-only, no training, no TP-shard streaming.
- Nemotron 3 Ultra (arXiv 2606.15007): GB200 NUMA process-binding hygiene only.
- Grace Hopper data-movement study (arXiv 2408.11556): characterization, no system.
- No prior work found combining TP with CPU-streamed weight shards for training. Angle appears untaken.

## Iteration log
- v1: SP + NVLink swap (relay). Rejected: mechanism-heavy, "NVLink use" not a contribution, lockstep protocol fragile.
- v2: multi-lane kernel sourcing. Rejected: not GB200-specific (R2 fail).
- v3: sTP. Survives R1-R6: kernels unchanged (only tile offsets + launch bounds per shard), parallelism itself does the dedup, GB200-only by lane/arena arithmetic, TP-baseline objection dissolved (we ARE TP, minus its blocker), distinct from 1-GPU story (parallelism + arena + scheduler are new).
- Convergence check (independent pass over R1-R6): no requirement changes -> CONVERGED at v3. Next change only if measurements (TP comm overlap, DRAM budget) contradict.
